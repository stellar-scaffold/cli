# Website

This website is built using [Docusaurus](https://docusaurus.io/), a modern static website generator.

## Installation

```bash
npm install
```

## Local Development

```bash
npm run start
```

This command starts a local development server and opens up a browser window. Most changes are reflected live without having to restart the server.

## Build

```bash
npm run build
```

This command generates static content into the `build` directory and can be served using any static contents hosting service.

## Deployment

There is a GitHub action deploying automatically the website when pushing changes to the website folder on main.

```bash
USE_SSH=true npm run deploy
```

We are using GitHub pages for hosting, this command is a convenient way to build the website and push to the `gh-pages` branch.

## Internationalization (i18n)

This site supports English (`en`, the default) and Spanish (`es`), configured in `docusaurus.config.ts`. Translated content lives under `i18n/es/`.

There are two independent things that need translating whenever the English source changes:

### 1. UI strings (navbar, sidebar labels, theme text, etc.)

These are extracted automatically. Run:

```bash
npm run write-translations
```

This runs `docusaurus write-translations --locale es`, which scans the site and:

- Adds any new/missing message keys to `i18n/es/code.json` and the other `i18n/es/**/*.json` files, using the English text as a placeholder.
- Leaves existing translated `message` values alone (it never overwrites a translation you've already written, unless you pass `--override`).
- Warns about keys that exist in `i18n/es/code.json` but are no longer used in the English source — these can usually be deleted.

After running it, search the changed JSON files for English placeholder text and translate it into Spanish, then commit the result.

> Note: `docusaurus write-translations` defaults to the site's `defaultLocale` (`en`) if no locale is given, which is a no-op for this project since English isn't translated from itself. Always pass `--locale es` (or use `npm run write-translations`, which does this for you) — do **not** use `--local`, which docusaurus silently interprets as a positional `siteDir` argument and fails with an `ENOENT` error.

### 2. Docs/blog page content

Unlike UI strings, the actual translated Markdown/MDX pages under `i18n/es/docusaurus-plugin-content-docs/current/` and `i18n/es/docusaurus-plugin-content-blog/` are **not** generated by `write-translations` — they must be created and kept in sync by hand:

- When a new page is added to `docs/` or `blog/`, copy it into the matching path under `i18n/es/docusaurus-plugin-content-docs/current/` (or the blog equivalent) and translate its content.
- When an existing English page changes, update its Spanish counterpart to match.
- Any page without a Spanish translation silently falls back to the English version, so missing translations won't break the build, but should be added over time.

To preview the Spanish site locally: `npm run start -- --locale es`.
